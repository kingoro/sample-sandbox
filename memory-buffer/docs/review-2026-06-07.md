# 全体整合性・モダン度レビュー

評価日: 2026年6月7日

## 総合評価

**92 / 100**

設計は古くない。Rust 2024、`no_std`、opaque handle、世代管理、呼出側提供RAM、
排他的pointer貸出、固定toolchain、C1 coverage gate、cbindgen、Miri、fuzz、
32 bit `no_std` cross buildを採用しており、
新規のRust/C混在memory libraryとして十分に現代的である。

## 内訳

| 分類 | 得点 | 評価 |
|---|---:|---|
| Architecture | 18 / 20 | 責務がbyte領域と所有状態に限定され、用途固有の知識を持たない |
| Memory safety | 18 / 20 | bounds・世代・map排他に加えMiriと操作列fuzzを導入。map pointerの利用契約は残る |
| API / ABI | 19 / 20 | version、size、alignment、offset、生成ABI manifestのdriftを検証 |
| Test / Quality | 19 / 20 | C1、CC、MI、C/Rust結合、Miri、fuzz、cross buildをgate化 |
| DevOps / Supply chain | 18 / 20 | toolchainとtoolを固定しcross-target CI化。依存監査とSBOMは未導入 |

## 今回確認・修正した事項

- `mb_map`を排他的貸出に変更し、二重mapを`MB_BUSY`にした
- map中の`mb_read`を`MB_BUSY`にし、貸出pointerとの競合accessを防止した
- `mb_set_length`で伸ばす範囲は外部書込み済みである契約を明記した
- context storageとarenaの重複およびaddress overflowを`mb_init`で拒否した
- 実装が返さない`MB_ALREADY_INITIALIZED`を公開APIから除去した
- ABI versionとC/Rust双方のsize・alignment・field offset検証を追加した
- C smoke testから全公開functionをlink・実行するようにした
- stable Rust、coverage用nightly、品質toolのversionを固定した
- `cbindgen --verify`によるRust ABI manifestのdrift検査を追加した
- Miriを追加し、テストfixtureのpointer provenance違反を検出・修正した
- libFuzzerによる公開API操作列fuzzと2000回のsmoke検査を追加した
- `thumbv7em-none-eabi`向けcross buildを追加した
- 32 bit cross buildで検出したenum ABI差異を`repr(u32)`と`uint32_t`で固定した
- 外部提供用の[C API仕様](api.md)を追加した
- 導入理由と検出実績を[高度検証](advanced-verification.md)へ記録した

## 最新水準との差

### Target検証

代表的な32 bit `no_std` targetへのcross buildは検証しているが、利用先targetでの
最終link、実行test、同期方式、memory属性は利用側での検証が必要である。

### 長時間動的検査

Miriと短時間fuzzはCIへ導入した。長時間fuzz corpusの継続保存、sanitizer、
allocator断片化とhandle世代周回のproperty testは追加余地がある。

### Header管理

Rust定義から生成するABI manifestはdrift検査している。外部向けheaderはopaque型と
Doxygen仕様を提供するため手動管理であり、compile-time assertion、C結合test、
生成manifestを組み合わせて整合性を検証する。

### Supply chain

`cargo audit`、license policy、SBOM生成、GitHub Actionsのcommit SHA固定は未導入。
製品release工程へ進む前に追加する価値が高い。

## 推奨改善順

1. 利用先targetの最終linkと実行testを追加する
2. 長時間fuzz corpusをCI間で継続し、重要caseをregression test化する
3. sanitizerとallocator断片化のproperty testを追加する
4. `cargo audit`、license検査、SBOMを追加する
5. GitHub Actionsをcommit SHAで固定する
